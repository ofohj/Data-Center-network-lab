# 주제: 네트워크 장비 종류 및 역할 파악

## 🏢 학습 목표
- 네트워크 장비 중 L2스위치/L3스위치/라우터 역할과 차이 설명하기
- 3-tier 구조에서 각 계층에 어떤 장비를 배치해야하는지 설명하기
- NIC의 역할 및 서버와 스위치 간 연결 구조 이해하기


## 🏢 장비 이해의 필요성
- 지난 시간에는 네트워크 구조에 대해 공부했다.
- 실무에서 네트워크를 구성하려면 구조 이해 + 각 계층에 어떤 장비를 배치해야하는지에 대한 지식이 필요하다.
- 이번 실습에서는 장비의 생김새와 기능을 공부하고 가상으로 연결해보면서 실무를 간접적으로 체험하려 한다.

## 🏢 사전지식
장비 간 연결 흐름은 다음과 같다.

💡 `서버 → NIC 포트 → 케이블 및 트랜시버 → 스위치/라우터`

이 중 오늘은 NIC와 스위치, 라우터에 대해 공부하려 한다.

## 🏢 1. 네트워크 장비의 역할과 차이
| 구분 | L2 스위치 | L3 스위치 | 라우터 |
| -- | -- | -- | -- |
| 경로설정 기준 | MAC 주소 | MAC, IP 주소 | IP 주소 |
| 작업 범위 | LAN 내부 | VLAN 간 고속 라우팅(주요 기능), 서로 다른 네트워크 간 통신 | 서로 다른 네트워크 간 통신 |
| 주요 기능 | 프레임 전달 | 스위칭+라우팅 | 라우팅 |

### ★ 추가 공부: 스위칭과 라우팅의 차이점
💡 `스위칭은 같은 네트워크 내 통신, 라우팅은 다른 네트워크 간 통신이라고 이해하면 될까?`

맞는 말이지만, 스위칭과 라우팅은 **통신범위**뿐만 아니라 **전달방식+참조하는 주소 정보**로 구분한다.

---
예를 들어, 같은 네트워크에 있는 서버 A가 B로 데이터를 보낸다고 가정해보자.

[데이터 전달 과정: 스위칭]
1. 서버 A가 목적지 IP를 확인한다.
2. IP 주소와 서브넷마스크를 통해 **같은** 네트워크에 있다고 판단한다.
3. ARP를 통해 서버 B의 **MAC 주소**를 알아낸다.
4. 이더넷 프레임을 생성한다.
5. L2 스위치가 목적지 MAC 주소를 확인하고 **프레임**을 전달한다.

▶️ 이처럼 `같은 네트워크 내에서`, `MAC주소`를 참조하여 `프레임`을 전달하면 스위칭!!

---
반대로, 다른 네트워크에 있는 서버 A가 B로 데이터를 보낼 경우,

[데이터 전달 과정2: 라우팅]
1. 서버 A가 목적지 IP를 확인한다.
2. IP 주소와 서브넷마스크를 통해 **다른** 네트워크에 있다고 판단한다.
3. 서버 A는 기본 게이트웨이의 IP 주소를 확인하고, ARP를 통해 게이트웨이의 MAC 주소를 알아낸다.
4. 게이트웨이(라우터 또는 L3 스위치)로 **IP 패킷**이 담긴 이더넷 프레임을 전달한다.
5. 라우터 또는 L3 스위치는 프레임에 담긴 IP 주소를 확인한다.
6. 서버 B의 **IP를 기준으로 라우팅 테이블을 참조**해 MAC 주소를 알아낸다.
7. 새로운 이더넷 프레임을 생성해 IP 패킷과 함께 목적지로 전달한다.

▶️ 이처럼 `다른 네트워크 내에서`, `IP 주소`를 참조하여 프레임에 더해 `패킷`을 전달하게 되면 라우팅!!

## 🏢 2. 3-tier 구조에서 장비 활용 방법
**1. Access 계층**
- 주요 장비: 서버와 연결하기 위해 `L2 스위치` 또는 `L3 스위치` 활용
- 역할: PC, 서버, 프린터, 스토리지 등 단말 연결
- 특징: 여기서 VLAN 할당

**2. Distribution 계층**
- 주요 장비: `L3 스위치`(경우에 따라 라우터나 방화벽 사용 가능)
- 역할: Access 계층의 트래픽 관리, VLAN 간 라우팅 및 ACL 정책 적용

**3. Core 계층**
- 주요 장비: `L3 스위치` 또는 `라우터`
- 역할: Distribution 계층 간 고속 트래픽 전달
- 특징: 높은 처리성능, 낮은 지연시간 요구, 이중화 필요

💡 **여기까지 공부하다보니 느낀점**
>: 네트워크에 무조건은 없다. 
일반적으로 자주 사용하는 장비는 정해져 있지만, 필요시엔 다른 계층에 있는 장비도 활용할 수 있다. 
그래서 실제 설계 시에 엔지니어는 자신만의 설계 철학이 필요한 것 같다. 
**실제 환경과 요구사항**에 맞춰 계층을 통합하거나 장비 배치를 다르게 구성할 줄 알아야 함!

## 🏢 3. NIC와 서버 연결 구조
### 1) NIC(Network Interface Card) 개요
- 컴퓨터나 서버를 네트워크에 연결하기 위한 하드웨어 장치
- 서버가 다른 서버나 네트워크 장비와 통신할 수 있도록 네트워크 인터페이스를 제공해줌

### 2) NIC 역할
- 데이터 송수신
- 이더넷 프레임 처리(IP 패킷 등의 데이터를 감쌈)
- MAC 주소 제공
- 전기 및 광 신호와 디지털 데이터 간 변환 지원

### 3) 장착 위치
- 서버 메인보드의 슬롯에 끼워넣는 형태
- 메인보드에 내장된 형태

▶️ `서버 본체에 NIC 장착 - NIC 포트에 케이블 연결 - 스위치의 이더넷 포트와 연결`

### 4) 데이터센터에서 NIC
- 데이터센터에서는 여러 대의 장비를 / 고속으로 연결해야 하기 때문에 ☞☞☞ 다중 포트+25GbE 이상을 지원하는 NIC 사용
