# 주제: 데이터센터 네트워크 구조 이해하기

## 🏢 학습목표
- 기업의 네트워크와 데이터센터의 네트워크 구조 차이를 이해하기
- 남북/동서 트래픽 차이 이해하기
- 3tier 및 Leaf-Spine 구조 비교하기

---
## 🏢 1. `기업용` vs `데이터센터` 네트워크 비교

| 구분 | 설명 |
| --- | --- |
| 기업 | 외부 사용자와 서비스 간 통신이 많음 |
| 데이터센터 | 내부 서버 간 대규모 통신이 많음 |
| AI DC | GPU 간 통신이 많아 초고속 네트워크가 요구됨 |

이 때, 외부-내부 간 통신을 North-South 트래픽, 내부 간 통신을 East-West 트래픽이라고 함

---
## 🏢 2. `남북` vs `동서` 트래픽 비교
남북/동서 트래픽은 서로 다른 네트워크 구조로 이루어진 것이 아니고, 동일한 네트워크 상에서 통신이 이루어지는 주체들이 외부인지 내부인지에 따라 달라짐.

### 1) 남북 트래픽 특징
- 네트워크 외부 ↔ 네트워크 내부 간 통신을 의미
- 예시상황: 사용자가 서비스에 접속한 경우
  1. (외부) 사용자 PC에서 웹사이트를 통해 접속 요청
  2. 인터넷을 통해 데이터센터로 패킷 전달
  3. 라우터 및 방화벽 통과
  4. 네트워크 장비를 통해 서버에 패킷 도착
  5. 서버의 응답을 사용자 PC로 전달
 
💡 남북 트래픽은 외부와 내부를 연결하므로 외부에서 내부로 들어오는 **접근을 통제하는 보안 정책** 이나 외부에서 내부로 들어오는 **패킷의 경로를 설정해주는 라우팅** 이 중요함!

### 2) 동서 트래픽 특징
- 네트워크 내부에서 이루어지는 통신을 의미
- 예시상황: 웹서버가 DB서버에 데이터를 요청한 경우
  1. 외부 사용자가 데이터를 요청함
  2. 웹서버가 DB서버에 패킷 전달
  3. DB서버가 웹서버에 응답
  4. 웹서버가 사용자에게 결과 전달
 
💡 동서 트래픽은 내부 장비 간 통신이므로 빠르게 데이터를 주고받을 수 있게 **대역폭, 지연시간, 혼잡제어나 경로 효율성**을 잘 설정하는 것이 중요함!

## 🏢 3. `3tier` vs `Leaf-Spine` 비교
### 1) 3tier 구조

- **계층 구조**

  - Core 계층: 네트워크 간 고속 트래픽 전달
  - Distribution(Aggregation) 계층: Access 트래픽 집계, 라우팅 및 접근 관리 정책 적용
  - Access 계층: PC 및 서버 등 엔드포인트 단말과 연결되는 부분

<img width="750" height="600" alt="image" src="https://github.com/user-attachments/assets/0161929e-28b1-4466-8611-126c416c24ac" />

- **특징**
  - 계층별 역할이 명확해서 관리하기 편리함(장애 발생 시 어떤 계층에서 문제가 생겼는지 파악이 쉬움)
  - 사용자 중심의 네트워크 구조로, 전통적인 기업 네트워크에서 많이 활용됨

- **데이터센터에 적용하면 생기는 단점**

  (1) 트래픽 전달 경로가 길어질 수 있음
  - Access-Distribution-Core 세 계층을 거쳐야하기 때문에 비교적 비효율적임
  - 또한 장애가 발생했을 때 관리 복잡도가 증가함
  
  (2) 네트워크 병목 현상
  - Access 스위치의 트래픽이 Distribution으로 집중되어 병목 발생 가능
  
  (3) 링크 활용의 비효율
  - 전통적인 3-tier 구조에서는 L2스위치를 사용하는 구간에서 STP로 인해 일부 경로가 차단됨
  - 서버 간 고속 통신이 요구되는 데이터센터 환경에서는 모든 링크를 사용할 수 없다는 점이 단점으로 작용
  - 다만 L3 라우팅 기반으로 설계하면 STP 의존성을 줄이고 ECMP 기술을 활용할 수 있

---

### 2) Leaf-Spine 구조
- Spine 계층: 모든 리프 스위치를 연결하는 백본 스위치
- Leaf 계층: 서버와 직접 연결되는 스위치

<img width="796" height="347" alt="image" src="https://github.com/user-attachments/assets/fac755e0-3732-4fe1-8adb-c604e2616c7e" />

- **특징**
  - 모든 Leaf는 Spine과 연결되며, 일반적으로 Spine끼리, Leaf끼리는 연결되지 않음
  - 여러 경로를 활용하여 트래픽을 분산할 수 있음
  - 대규모 서버 및 GPU 클러스터가 있는 데이터센터에 적합한 구조

---

### 3) 데이터센터에서 Leaf-Spine이 선호되는 이유

데이터센터에서 전통적인 방식인 3-tier 보다 Leaf-Spine이 선호되는 이유를 그림으로 표현했다.
대규모 데이터에서는 서버 간 초고속 통신을 위 간소화된 계층으로 구성된 Leaf-Spine을 선호한다.
