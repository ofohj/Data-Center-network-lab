# 주제: 케이블 및 트랜시버의 이해

## 🏢 케이블의 종류 및 개념 비교
케이블은 데이터를 어떤 **재료와 신호**로 전달하는지에 따라 종류가 달라진다.
여러 종류의 케이블 중 데이터센터에 자주 사용되는 4가지 케이블을 선정했다.

### 1. UTP 케이블
| 구분 | 설명 |
| -- | -- |
| 재료 | 구리선 |
| 신호 | 전기 신호 전달 |
| 구조 | 양끝에 RJ45 커넥터를 연결시켜 사용 |
| 활용 | 주로 PC와 서버, 네트워크 장비 간을 연결 |

### 2. 광케이블
| 구분 | 설명 |
| -- | -- |
| 재료 | 광섬유 |
| 신호 | 광 신호 전달 |
| 구조 | 장비의 광 트랜시버에 광케이블을 연결하는 구조ㅍ
| 활용 | 장거리 및 고속 통신에 적합 |

### 3. DAC(Direct Attach Copper)
| 구분 | 설명 |
| -- | -- |
| 재료 | 구리선 |
| 신호 | 전기 신호 |
| 구조 | '직접/연결/구리'라는 이름에서부터 알 수 있듯이, 구리 케이블 양 끝에 트랜시버 형태의 커넥터가 일체형으로 연결되어 있음 |
| 활용 | 짧은 거리의 고속 연결에 적합(ex. 같은 랙 안의 서버-스위치 연결) |

### 4. AOC(Active Optical Cable)
| 구분 | 설명 |
| -- | -- |
| 재료 | 광섬유 |
| 신호 | 광 신호 |
| 구조 | 양 끝에 광전 변환 회로가 일체형으로 구성되어 있어 별도의 광 트랜시버를 조합할 필요가 없음 |
| 활용 | DAC보다 상대적으로 긴 거리 고속 연결에 적합(ex. 랙 간 스위치 연결) |

## 🏢 트랜시버의 개념 및 기본 규격 이해

### 1. 개념

- 컴퓨터는 전기신호만 처리할 수 있다.
- 그런데 빠른 속도로 정보를 주고받기 위해서는 광신호를 사용해야한다.
- 이 때, 컴퓨터가 신호를 처리할 수 있도록 광케이블에서 컴퓨터로 들어오는 광 신호를 전기 신호로 바꿔주고, 컴퓨터의 전기 신호를 광 신호로 바꿔주는 것을 **트랜시버**라고 한다.

### 2. 기본 규격

- 트랜시버는 폼팩터에 따라 종류가 나뉜다.
- 폼팩터: 하드웨어의 크기, 모양, 물리적 구조, 외형 등을 의미하는 규격
- 폼팩터에 따른 종류:
  
  | 폼팩터명 | 대표적인 Ethernet 속도 | 특징 |
  | -- | -- | -- |
  | SFP(Small Form Factor Pluggable) | 1GbE | 단일 레인(경로)을 1GbE 속도로 사용 |
  | SFP+ | 10GbE | 단일 레인을 10GbE 속도로 사용 |
  | SFP28 | 25GbE | 단일 레인을 25GbE 속도로 사용 |
  | QSFP+(Quad Small Form Factor Pluggable) | 40GbE | 레인 4개를 40GbE 속도로 사용 |
  | QSFP28 | 100GbE | 레인 4개를 100GbE 속도로 사용 |
  | QSFP-DD(Double Density) | 400GbE | 레인 8개를 400GbE 속도로 사용 |

  - QSFP는 SFP보다 크기도 크고 빠르다
  - 표에 나온 속도는 대표적인 속도이며, 실제 지원 속도는 모듈 사양을 확인해야 한다.
 
## 🏢 3-tier 네트워크 물리적 구성 및 배선도

### 1. 연결 필요 구간
| 구분 | 연결대상 | 연결목적 |
| -- | -- | -- |
| 계층 간 | Core-Distribution | 상위 네트워크 연결 |
| 계층 간 | Distribution-Access | 하위 네트워크 연결 |
| 계층 간 | Access-Server | 서버 연결 |
| 계층 내 | Core-Core | 장비 이중화 |
| 계층 내 | Distribution-Distribution | 장비 이중화 |

```
※ 주의할 점: 무조건 이중화를 하는 것이 안전한 것은 아니다.
             그만큼 관리가 복잡해지고, 루핑과 같은 장애 확률이 발생한다.
             네트워크 환경 구성 목적에 따라 설계해야 함!
```

### 2. 네트워크 환경 가정 및 구성

```
본격적으로 프로젝트 수행을 위한 네트워크 환경을 가정해보려 한다.
요즘 통신사, 금융회사, 공공기관 가리지 않고 해킹 사고가 빈번하다.
이에 여러 네트워크 특성(가용성, 확장성, 성능 등) 중 보안성에 가장 무게를 두려한다.
```
#### (1) 프로젝트 환경
- **주제:** IT 서비스 기업의 데이터센터
- **데이터센터 목적:** IT 서비스 기업에서 사내 개발팀과 서비스 운영팀에 클라우드 자원을 제공하는 데이터센터
- **주요 사용자:** 개발팀, 서비스 운영팀, 인프라팀(네트워크 접근 권한을 다르게 설정하기 위해 팀을 구분함)

#### (2) 네트워크 구성 방향
- 개발망, 운영망, 관리망, 스토리지망을 구분하여 구성
- 각 네트워크 영역 간 불필요한 통신 차단
- 핵심 네트워크 장비 및 연결 경로 이중화
- 향후 서버 및 서비스 증가에 대응할 수 있도록 확장성 확보

### (3) 물리적 구성도

아래 구성도는 가상의 데이터센터 네트워크 구조를 나타낸다.

실제 데이터센터에는 다수의 네트워크 장비와 서버가 배치되지만, 본 구성도에서는 전체 네트워크 구조와 계층별 연결 관계를 명확하게 전달하기 위해 주요 장비를 그룹 단위로 단순화하여 표현하였다.
